Pico Latency Tester

A small device that measures the delay between a mouse click and the screen changing.

This device measures the time between a mouse click and the screen actually changing. That delay includes the USB connection, the operating system, the game, the graphics card and the monitor, which makes it a useful way to compare game and display settings. It also confirms that a device such as the MixPad does not add any delay.

How it works

  1. Read the screen's brightness and noise with a light sensor held against the monitor.
  2. Send a click as a 1000 Hz USB mouse and start a microsecond timer.
  3. Stop the timer when the brightness moves past a threshold set from the measured noise.

Each run takes 100 measurements with random pauses in between, so the clicks never line up with the monitor's refresh. The device shows the average and spread on its display, and a Python script can log every measurement to a CSV file.

Why C++

I first planned to use CircuitPython, but its source code showed that it only reports USB input every 8 milliseconds. That would have added up to 8 ms of error to every measurement, so I wrote the firmware in C++ with TinyUSB, which reports every millisecond.

Results

I measured the Windows desktop on a 1080p 240 Hz monitor with an RTX 5070 Ti, using a full-screen window that turns white on each click. Three identical runs at 240 Hz gave the same median to within 0.1 ms, so the tester itself is consistent.

Refresh rateMedian5th–95th percentile
60 Hz62.2 ms54.6–70.2 ms
144 Hz28.4 ms25.2–31.7 ms
240 Hz18.3 ms16.1–21.6 ms

Going from 60 Hz to 240 Hz cut the delay by 71 %. The results fit about 3.8 ms plus 3.5 refresh periods, because the Windows desktop draws in whole frames, so the refresh rate matters more than raw speed suggests. The spread at each rate is about one refresh period, which is what clicks landing at random points in the refresh cycle would give.
